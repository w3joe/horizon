# Local CPU runtime

Run `./scripts/bootstrap.sh` once, `./scripts/check.sh` for the full repository checks, and `./scripts/launch_cpu.sh` for the local slice. The scripts select Python 3.12 at `/opt/homebrew/bin/python3.12` when available and otherwise require Python 3.11 or newer. Set `HORIZON_PYTHON` to override the interpreter.

| Component | Port | Current launch behavior |
|---|---:|---|
| Console | 5173 | Built with `/api` as its read-only simulator endpoint and served by the local proxy |
| A06 authoring preview | 5176 | Reserved; never bound by the integrated launcher |
| Simulator | 8100 | Started and health-checked |
| Decision-AI fixture | 8101 | Started as a separate process and health-checked |
| Gate | 8102 | Own process with independent watchdog and exclusive protected-plant capability |
| Assurance | 8103 | Runs the selected A1-A5 candidate at 20 Hz over fresh fused input |
| Fusion | 8104 | Polls collector and Decision AI, then serves fresh `GovernorInput` records |
| Collector | 8105 | Polls the protected simulator branch and buffers bounded observations |

The launcher refuses occupied ports before starting each process. A launch receives a UTC/random run ID and a new external run directory. Set `HORIZON_RUNS_DIR` to choose another external root. The protected loop uses A5 by default for the normal showcase; `--candidate A1`, `A2`, `A3`, `A4`, or `A5` selects another implemented candidate explicitly. The exact selection is passed to the assurance process, recorded as `candidate_id` in `run.json`, and returned by the console `/health` status. Public assurance evidence and telemetry continue to expose the candidate ID on their existing decision records. `run.json` also records the commit, ports, ready processes, unavailable components, smoke results, PIDs, exit codes, and start/stop timestamps. A component exit ends the complete run without an automatic restart and records the failure type and message.

The recorded-demo capture also defaults to A5 and accepts the same explicit `--candidate` choices. `--marine-config` applies a versioned sea-state configuration to the simulator, while `--run-id` and `--title` name the frozen artifact. Its manifest records the assurance candidate ID and observed implementation version, plus either the simulator-default marine mode or the selected configuration's repository-relative identity and SHA-256. External configuration provenance uses only the basename and hash, never an absolute host path. Configured marine modes currently remain assurance-unqualified, so the recorder stops without writing an artifact when such a run cannot produce accepted assurance evidence. The run ID must satisfy the console's existing lowercase demo allowlist; changing it without `--output` also changes the default external artifact directory.

SIGINT or SIGTERM stops only process groups created by the launcher. It first sends SIGTERM, waits up to five seconds, and then uses SIGKILL only for an owned child that did not exit. A finite `--smoke-seconds N` run follows the same shutdown path. Startup order is simulator, Decision AI, collector, fusion, gate, assurance, then console. Startup verifies every process health endpoint, the console-to-public-simulator path, the `display_only` boundary, and a full observation-to-command chain. It declares readiness only after a joined `GovernorInput`, `AssuranceDecision`, and accepted `GateReceipt` has matching identities, the receipt command ID appears in a later public plant snapshot, and a later fused actuator observation is captured. The run record stores before/after speed, rudder, thrust, simulation time, and monotonic time; this is observed feedback around the command, while the active command ID proves receiver state rather than physical tracking by itself.

The console proxy uses an explicit read-only allowlist. Legacy `/api/v1/public/*` routes reach the simulator; `/api/{collector,fusion,assurance,gate}/*` reaches only each service's documented health, diagnostics, telemetry, evidence, and bounded input routes. Plant truth, gate decision writes, recovery priming, and evaluation routes are rejected at the proxy.

`GET /api/operator/capabilities` reports the protected branch's plant epoch, gate epoch, recovery readiness, declared fault IDs, and whether resume is permitted. Operator POSTs require `Content-Type: application/json` and `X-Horizon-Operator: 1`; the proxy reads the run-specific capability file and injects the bearer only on the fixed upstream route. Reset first pauses and resets the plant, then leaves it paused while the assurance loop waits for new-lineage observations, rotates the gate decision token, and primes a recovery. Resume returns HTTP 409 until plant and gate epochs match and `startup_recovery_ready` is true. Resume and quarantine acknowledgement always require separate explicit operator actions.

The current simulator queues reset sensor samples at positive simulation ticks, so a paused plant cannot yet deliver the fresh observations needed to finish recovery priming. Reset therefore remains safely paused with `reset_in_progress`; it does not silently reuse pre-reset input or resume. Normal startup records this limitation without exercising reset. `--verify-reset` makes the bounded smoke require reset, recovery priming, explicit resume, and a new-epoch receipt; it currently fails closed until the simulator provides paused reset sensor delivery.

When the completed local WaSR-T reproduction is present, `/api/artifacts/perception` indexes its 85 recorded frames. Availability requires a valid 85-line feature file, finite compact statistics, all raw images with hashes matching the manifest, and every nonempty class mask and preview. Missing or malformed artifacts make the index unavailable without preventing console startup. `/manifest` returns the pinned reproduction manifest and `/frames/{00000}` returns timing plus finite/minimum/maximum/mean/standard-deviation statistics for each instrumented layer. The response omits pooled activation vectors and links to allowlisted `/raw`, `/mask-preview`, and `/class-mask` image routes. This artifact is recorded perception reproduction evidence with synthetic 10 Hz order timestamps; it is not a live simulator camera feed or safety truth.
