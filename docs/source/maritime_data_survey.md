# Public maritime data and repositories for HARBOR

Inspected **21 September 2026**. This is a practical, broad survey of 25 resource groups, not an exhaustive catalogue. These are public civilian/research proxies relevant to maritime navigation safety; they are not authenticated operational naval datasets. Recommendations concern navigation, perception integrity, communications integrity and safety intervention.

**Best five integration choices:** (1) WaSR-T with MODS for perception-health experiments; (2) CANOE for genuine multisensor replay; (3) MANA/MARSIM for labeled onboard NMEA network anomalies; (4) Signal K/CANboat for realistic vessel-data adapters; (5) VRX for closed-loop intervention and visually convincing simulation. WaterScenes is the best additional labeled radar-camera fusion option, subject to its noncommercial data terms. Resources and evidence are detailed below.

**Evidence levels:** `READY` = publicly documented code/data path and sufficiently clear initial use; it does not mean execution tested. `CONDITIONAL` = access, rights, compatibility or incomplete annotations need resolving. `SYNTHETIC` denotes generated data, independent of readiness. Only the two small files in the next section were downloaded and parsed. Large data archives, model weights and applications were not downloaded or run. No registrations or terms-acceptance forms were submitted.

## Vision and interpretable perception

1. **WaSR-T — model/code, READY.** Official PyTorch temporal water/sky/obstacle segmentation, pretrained weights and an 85-image example sequence. Code MIT; retain separate data/weights provenance rather than assuming MIT licenses all training imagery. Older pinned dependencies need an isolated reproducible environment. Start with `predict_sequential.py` on `examples/sequence`, the MaSTr1325 checkpoint and recorded encoder activations. Clear temporal state between clips; otherwise previous sequences contaminate predictions. Model inference was not run here. [Official repository](https://github.com/lojzezust/WaSR-T).

2. **WaSR — baseline model/code, READY.** Single-frame PyTorch reimplementation with pretrained checkpoints and evaluation workflow; code Apache-2.0. Useful matched baseline for determining whether temporal context and activation monitoring add value. First reproduce its example prediction using the same evaluation clips as WaSR-T; record preprocessing and checkpoint hash. Dataset and checkpoint conditions should be recorded separately. [Official repository](https://github.com/lojzezust/WaSR).

3. **MaSTr1325 — real onboard dataset, CONDITIONAL on data terms.** 1,325 coastal-USV RGB images, per-pixel labels, synchronized GPS/IMU information. Labels: obstacle 0, water 1, sky 2, ignore 4. Suitable nominal feature dictionary/SAE training material; the number of images is modest and the geographic domain narrow. Official download landing page exists; explicit data licensing was not established in this inspection. Obtain images, masks and calibration/metadata from that page; keep training and monitor-calibration partitions disjoint by recording session. WaSR-T adds temporal context separately. [ViCoS dataset page](https://www.vicos.si/resources/mastr1325/).

4. **MODS — real benchmark plus evaluator, CONDITIONAL on data/code terms and hosting.** Official repository links full data through institutional SharePoint, example WaSR masks through Drive, and contains ground truth and Python evaluation/visualization. Evaluates water-edge error and obstacle TP/FP/FN, including danger-zone results. First run the supplied prediction-mask example before integrating a model. Do not adopt its fixed benchmark danger zone as a large-vessel stopping envelope. No standalone license was visible in the repository root listing inspected; record explicit terms before redistribution. [Official benchmark](https://github.com/bborja/mods_evaluation).

5. **MODD2 — real calibrated onboard video, CONDITIONAL on data terms.** 28 sequences with video/IMU, calibration sequences, raw/rectified annotations and own-vessel masks. Water-edge polygons and obstacle boxes support horizon/IMU consistency and glare/motion stress cases. Evaluation repository is GPL-3.0; separate dataset rights need confirmation. Retrieve one sequence with matching calibration and annotation variant; use the published calibration demo to validate the horizon before any ground-plane projection. Do not mix raw image coordinates with rectified annotations. [Dataset/evaluator](https://github.com/bborja/modd), [camera-IMU calibration](https://github.com/bborja/camera-imu-calib).

6. **LaRS — real/mixed-source panoptic dataset, CONDITIONAL.** Over 4,000 labeled keyframes plus nine preceding frames; PNG semantic masks and COCO panoptic annotations. Broader domain shift testing than a single harbor. Download page has a name/email/affiliation form and terms; no form submitted. Images/annotations are CC BY-NC 4.0 with additional stated scientific-use/access and no-direct-redistribution conditions. Start with train/validation keyframes after satisfying access requirements; temporal archive is much larger. Audit source overlap with other maritime datasets before claiming an independent test set. [Dataset/formats](https://lojzezust.github.io/lars-dataset/), [terms](https://lojzezust.github.io/lars-dataset/terms.html).

7. **MassMIND — real thermal dataset, READY for compatible noncommercial research.** 2,916 LWIR images at 640×512, semantic/instance masks across seven classes, recorded around Boston Harbor. Data/benchmarks CC BY-NC-SA 4.0. Useful thermal branch and day/night robustness evaluation; it does not supply a synchronized radar-camera-AIS voyage. Start with linked image and mask packages and one segmentation baseline. Never feed LWIR into an RGB checkpoint and describe the resulting uncertainty as calibrated. [Official repository](https://github.com/uml-marine-robotics/MassMIND).

8. **Singapore Maritime Dataset — real RGB/NIR video, CONDITIONAL on license.** Author page links 81 annotated videos: 40 visible shore, 11 visible onboard and 30 NIR shore clips, with horizon/detection/tracking ground truth. NIR is not LWIR thermal. The onboard subset is the closest viewpoint match; shore cameras can support a port-observer panel. Explicit reuse license not established. Retrieve onboard video and matching GT description first; do not assume the three subdatasets are synchronized views of the same scene. [Author dataset page](https://sites.google.com/site/dilipprasad/home/singapore-maritime-dataset).

9. **SeaDronesSee — real aerial SAR imagery, CONDITIONAL/optional.** Public institutional benchmark for object detection and single-/multi-object tracking; official page links code and challenge downloads. Useful swimmer/rescue-vessel visual examples, but aerial viewpoint and tasks are different from shipboard free-space estimation. Start with a small official validation subset and labels; record the exact challenge/version and data terms before use. Do not combine v1/v2 subsets without deduplication. The landing page alone did not establish a blanket license. [Official benchmark](https://seadronessee.cs.uni-tuebingen.de/).

## Multisensor vessel replay

10. **WaterScenes — real radar-camera dataset/devkit, READY for compatible noncommercial research.** 54,120 sets of RGB, 4D radar point clouds, GPS and IMU; timestamps and intrinsic/extrinsic calibration. JPEG/CSV/TXT plus box, point and segmentation labels. Data CC BY-NC-SA 4.0; no distinct code license detected by GitHub metadata. The official README links a sample and full Google Drive/Baidu packages. Start with the official sample and `Tutorial.ipynb`; validate radar projection and timestamp tolerances. Inland waterways and automotive-style 4D radar are not equivalent to a naval marine radar. [Official repository and sample links](https://github.com/WaterScenes/WaterScenes).

11. **CANOE + pycanoe — real multisensor dataset/devkit, READY.** UTIAS supplies 360° radar, LiDAR/IMU, stereo cameras, imaging/sidescan sonar, GNSS and motor inputs. Data CC BY 4.0; devkit BSD-3-Clause. Public S3 permits unsigned access and selecting individual sensors. Timestamped PNG/BIN/CSV/XTF data plus transforms support synchronized replay; it is primarily navigation/localization data, not a fully obstacle-labeled corpus. First list `s3://canoe-data/` with `aws s3 ls --no-sign-request`, then retrieve calibration and a short sensor window. Do not load post-processed trajectory ground truth into the online state estimator. [AWS registry](https://registry.opendata.aws/canoe/), [devkit](https://github.com/utiasASRL/pycanoe), [data reference](https://github.com/utiasASRL/pycanoe/blob/main/DATA_REFERENCE.md).

12. **Pohang Canal + PoLaRIS — real multimodal navigation and annotations, CONDITIONAL.** Canal/port/coastal sequences contain marine radar, stereo/IR/omnidirectional imagery, three LiDARs, AHRS and RTK GPS with calibration. Public unsigned S3 route; some files exceed 100 GB. Pohang data CC BY-NC 4.0. PoLaRIS adds object detection/tracking annotations, but the inspected README explicitly provides sequences 00/01 only; verify separate annotation terms. First list objects and select a modality/sequence, then pair matching PoLaRIS labels. Do not count PoLaRIS as an independent capture source. [Pohang download instructions](https://github.com/dhchung/pohang_canal_dataset), [PoLaRIS](https://github.com/sparolab/PoLaRIS).

13. **USVInland — real multisensor dataset, CONDITIONAL.** LiDAR, stereo camera, radar and INS for SLAM/odometry, stereo matching and water segmentation. Official repository points to the ORCA institutional download site; that destination failed during this inspection and code/data license was not established. Useful candidate for inland-domain generalization, not a dependency for the first reproducible demo. Next step is to verify the official download site and obtain one calibrated sequence and task labels, without relying on undocumented mirrors. [Official repository](https://github.com/ORCAUBOAT/USVInland-Dataset).

14. **SeePerSea — real labeled LiDAR-camera dataset, READY for compatible noncommercial research.** Ego-centric in-water obstacle perception; sample data and GUI viewer linked in the official repository. PNG images, PCD point clouds, TXT calibration and synchronized timestamps support projection; labels/splits supplied in documented formats. Dataset/benchmarks CC BY-NC-SA 4.0; do not infer a separate permissive code license. Start with the official Drive sample and viewer, then inspect one synchronized image/point-cloud pair. It fills LiDAR-camera agreement tests, not radar/network/decision-log gaps. [Official repository](https://github.com/dartmouthrobotics/SeePerSea).

## AIS, network and communications

15. **MarineCadastre AIS — real historical trajectories, READY via bulk access.** NOAA/BOEM/USCG public vessel positions support civilian encounters and traffic context. Download one day, spatially crop and preserve MMSI/time/SOG/COG/heading plus missing-value flags. The AccessAIS custom ordering page currently states the service is unavailable and directs users to bulk downloads; do not make the demo depend on its email workflow. AIS is self-reported/intermittent and is not independent ground truth or a transcript of inter-ship decisions. Follow source metadata and government-material attribution terms. [AccessAIS status](https://marinecadastre.gov/accessais/), [bulk access](https://marinecadastre.gov/ais/), [NOAA reuse FAQ](https://coast.noaa.gov/data/marinecadastre/ais/faq.pdf).

16. **Heterogeneous Integrated Maritime ISR dataset — real civilian AIS/context, CONDITIONAL on component licenses.** Six months of Brittany/Channel/Biscay AIS with vessel, geographic and environmental context; PostgreSQL/PostGIS integration queries. Public Zenodo lists individual archives, including a 201 MB AIS archive and tiny schema/query files. Useful harbor scene/context construction, not shipboard radar or classified ISR. Retrieve integration queries and status-code metadata first; inspect each underlying provider's rights before combining/rehosting. The rendered record did not clearly expose a single blanket license. [Original dataset record](https://zenodo.org/records/1167595).

17. **MARSIM + MANA — SYNTHETIC labeled network data plus detector code, READY.** 43,320 two-minute PCAPs of benign/spoofed NMEA0183 GPS streams, two simulated receivers; JSON labels/parameters. Dataset is **CC BY 4.0**, confirmed in Zenodo API metadata; compressed archive ~560 MB. MANA is supplemented MIT (third-party rights excluded) and has offline detection examples. Download the archive separately, choose one benign/fault pair and run the dataset example. These are simulated two-receiver PNT streams, not broad operational ship traffic. Keep packet timestamps and label onset; do not train/test split near-identical parameter-grid cases randomly. [Data](https://zenodo.org/records/8202936), [MANA](https://github.com/fkie-cad/mana), [dataset description](https://github.com/fkie-cad/mana/blob/main/README_MARSIM.md).

18. **Signal K server — adapter/replay code with samples, READY.** Apache-2.0; NMEA0183/NMEA2000 input and structured HTTP/WebSocket vessel data. Current official Docker guide provides `--sample-nmea0183-data`; developer guide marks N2K sample data as synthesized. Download-verified NMEA sample above is immediately useful for parsing, not capture-timing validation. Start a locally bound sample server, subscribe to deltas, and preserve raw sentence/source beside normalized values. A Signal K gateway is an integration layer, not independent corroborating evidence. [Server](https://github.com/SignalK/signalk-server), [sample Docker guide](https://github.com/SignalK/signalk-server/blob/master/docker/README.md), [synthetic N2K sample documentation](https://github.com/SignalK/signalk-server/blob/master/docs/develop/plugins/README.md).

19. **CANboat — NMEA2000/CAN parser and fixtures, READY code; CONDITIONAL data provenance.** Apache-2.0 repository with PGN decoder, sample captures and text/JSON conversion. Supports common gateway formats and CAN dumps. Next retrieve one small sample, decode offline and preserve PGN, source/destination, arrival time and invalid values. Code license does not demonstrate that samples represent a fault-labeled maritime network benchmark. Published implementation is not a substitute for licensed normative NMEA/IEC standards or device-specific conformance evidence. [Official repository](https://github.com/canboat/canboat).

20. **MARTTS — SYNTHETIC radio dialogue/text/audio, READY text; CONDITIONAL noisy audio.** DLR dataset advertises 240 generated maritime VHF dialogues; JSONL scenarios, clean/noisy audio and speaker/noise metadata. Zenodo API and README declare CC BY 4.0. The 80-record text file above is inspected. Use it for communications parsing; synthetic timestamps added by HARBOR must be marked as generated. **Audio rights discrepancy:** MARTTS README describes ESC-50 as CC BY, while ESC-50 itself identifies CC BY-NC. Do not rely on the top-level license for unrestricted noisy-audio redistribution until underlying clips are checked. [MARTTS](https://zenodo.org/records/19205712), [MARTTS README](https://zenodo.org/api/records/19205712/files/README.md/content), [ESC-50 source](https://github.com/karolpiczak/ESC-50).

21. **VHF-Dial / DASH-DTS — real civilian public-channel dialogue text, CONDITIONAL.** Authors describe real maritime VHF topic-segmentation data; repository includes `dataset/vhf.json` (~805 kB), confirmed through GitHub metadata. Code repository Apache-2.0; a separate detailed dataset provenance/consent/license statement was not established. Primary scope includes vessel-regulator dialogue and some ship-to-ship communication; not naval internal comms. Next inspect local JSON structure and annotation units, retaining source labels; do not assume raw audio, radio-channel packet data or synchronized vessel sensors are available. [Paper](https://arxiv.org/abs/2512.15042), [official repo](https://github.com/StanleySun233/dash-dts), [data file](https://github.com/StanleySun233/dash-dts/blob/main/dataset/vhf.json).

## Simulation and neural inspection

22. **VRX — simulation/scenarios, READY; generated data SYNTHETIC.** Apache-2.0 maritime USV Gazebo environment with WAM-V and RobotX tasks. Official recommended configuration is ROS 2 Jazzy/Gazebo Harmonic; pin a commit and compatible environment. Start a documented world, attach/record sensor topics and implement a separate proposal-to-actuator safety gate. Visually attractive ocean simulation plus a browser dashboard can expose proposed/applied paths and intervention causes. Robot-scale dynamics do not validate full-size ship stopping/turning behavior. [Official repository and documentation links](https://github.com/osrf/vrx).

23. **MOOS-IvP + missions-auto — marine autonomy/scenario code, READY; generated logs SYNTHETIC.** Modular autonomy middleware and helm, useful as the separate decision system rather than burying decisions inside the governor. Core licensing mixes GPLv3/LGPLv3; missions-auto GPL-3.0. Start with an included obstacle-avoidance/ownship mission and record proposal, state and inter-process messages. Automated missions can drive regression tests, but neither repository supplies validated military comms. [Core](https://github.com/moos-ivp/moos-ivp), [licensing](https://github.com/moos-ivp/moos-ivp/blob/main/COPYING.md), [automated missions](https://github.com/moos-ivp/missions-auto).

24. **Captum — neural inspection code, READY.** BSD-3-Clause PyTorch interpretability library. LayerActivation, LayerConductance and attribution tools support inspecting intermediate CNN behavior. Begin with one WaSR layer and an obstacle-region scalar output; compare nominal/degraded frames while measuring overhead. Gradient attribution is explanatory evidence, not proof of causal necessity or a calibrated safety sensor. Preserve input, model hash, layer name and monitor version. [Official code/license](https://github.com/meta-pytorch/captum), [layer API](https://captum.ai/api/layer.html).

25. **Baukit — internal tracing/intervention utilities, CONDITIONAL on license verification.** `Trace`/`TraceDict` capture internal PyTorch activations; output editing supports controlled offline interventions. First trace a selected WaSR block and save pooled activations; later compare ablation/patching against matched controls. Check the pinned repository LICENSE before distribution (not resolved in this survey). The repository provides instrumentation, not a pretrained maritime SAE or validated perception-health detector. Avoid perturbing the live control-path network merely to produce an explanation. [Official repository](https://github.com/davidbau/baukit).

## What must still be generated or instrumented

- **No unified dataset found** that synchronizes ship sensors, packet captures, internal human communications, inter-ship dialogue, a separate autonomous planner's decisions and neural activations. Do not align unrelated datasets by wall clock and call the result a recorded voyage.
- **Internal bridge/engineering communications:** no suitable openly licensed operational corpus verified here. Generate explicit scenario messages with speaker role, source identity, issue/expiry time and acknowledgment state. Keep internal/inter-ship channels distinct.
- **Inter-ship machine cooperation:** AIS supplies reported state, and VHF corpora supply dialogue; neither proves an authenticated maneuver agreement. Generate a clearly marked safety-coordination protocol and loss/delay/duplicate/conflict fixtures in simulation.
- **Decision-AI telemetry:** instrument the separate planner to emit proposed command/trajectory, world-state version, constraints, uncertainty, evidence IDs and deadline. Textual explanations are not trusted access to model internals. Open-weight perception allows activation hooks; a black-box sensor does not.
- **Ship engineering and actuation faults:** add synthetic rudder/thruster feedback, engine RPM/power, actuator delay/saturation, depth, wind/current and independent timebase. CANOE motor inputs are useful examples but do not replace a ship propulsion/steering model.

## Recommended integration contract and evaluation

Maintain separate **recorded replay**, **closed-loop simulation** and **synthetic fault overlay** modes. Recorded imagery does not change when the simulated ship turns; its results can test perception/monitoring, but it cannot demonstrate the camera view after a counterfactual evasive maneuver.

Every event should carry `source_dataset`, `sequence_id`, `sample_id`, `event_time`, `ingest_time`, `timebase`, `coordinate_frame`, `units`, `source_identity`, `quality_flags`, `synthetic`, `raw_artifact_hash` and `license_reference`. Preserve calibration and raw payloads. Track sensor measurements and derived gateway messages as the same evidence lineage, not independent votes.

Use replay to evaluate held-out obstacle misses, representation novelty, timestamp faults and cross-sensor disagreement. Use closed-loop scenarios to measure minimum separation, grounding, speed limits, intervention lead time, control smoothness, deadline misses and unnecessary takeover. State any safety claims relative to the vessel dynamics, sensor uncertainty and disturbances actually modeled.

Split by voyage/session/location, not adjacent frames. WaSR/WaSR-T share training families; MaSTr1478 extends MaSTr1325; PoLaRIS annotates Pohang; LaRS incorporates multiple source collections. Audit filenames, hashes and near duplicates across all splits. Freeze neural monitor thresholds before the final test set; compare confidence-only, conventional health checks, and conventional checks plus activation monitoring. Do not equate an attractive activation heatmap with successful mechanistic interpretation.

Next concrete work: reproduce WaSR-T/MODS; obtain one CANOE sensor window; replay a MARSIM benign/fault pair through the same ingestion contract; connect the already-inspected Signal K sample; generate an instrumented VRX scenario with a separate planner and deterministic governor. Add MARTTS text and conditional VHF-Dial as communications fixtures, with a visible provenance badge on every demo stream.
